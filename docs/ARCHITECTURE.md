# 架构与运行边界

HA 事件循环只负责实体与状态通知。DDS 初始化、类型构建、读取、查询、清理均在独立 worker 线程中执行。线程通过事件循环的 call_soon_threadsafe 发布独立状态快照；配置卸载会通知退出并等待线程结束。

DdsClient 不在导入时加载原生库，不使用全局 CYCLONEDDS_URI；每个 domain 使用显式 XML 配置。当前在 HA 中仅计划支持一个该网关配置条目；多 domain / 多网关共存仍待验证。实际 schema 包含四种 LanProto 消息的 TypeIdentifier 和 TypeMapping。

只读模式不创建 ChangeAttribute Topic 或 DataWriter，command() 在使用任何 native writer 前拒绝。查询使用独立消息 ID，只接受设备和消息 ID 匹配的答复。属性状态拒绝较旧时间戳、无时间戳覆盖有时间戳以及相同时间戳的冲突值。

未解决的边界：网关时钟跳变可能需要显式重置缓存策略；原生库崩溃放入 HA 进程后会扩大影响范围。当前真机检查运行在独立 Python/HA Core 进程中并保持只读，没有在现用 HA 加载原生库。

预览模块仅为只读传感器。正式控制不会直接把当前 MQTT 状态模板复制过来，需要独立建立实体模型和反馈校验，并保留现有已验证命令语义。

0.2.0-dev：六类实体已有独立实现，默认只读。显式启用控制时命令经有界队列送到 DDS 线程；反馈匹配后才返回，不修改状态缓存作乐观确认。超时、卸载、断线均结束等待且不重放命令。窗帘长行程可根据新位置进度或新的运动回报确认开始，不要求 7 秒内走完全程。反馈只证明网关返回了相符状态，不替代对实际设备动作的观察。
